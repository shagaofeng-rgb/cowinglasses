# CoWin 库存、询价与搜索运维

## SKU 现货核对

1. 在后台 **库存管理** 筛选 **待核实**，按 SKU 逐个盘点默认仓的实物。
2. 填写实物总数、预警阈值和盘点依据。实物总数包含已预留件数。
3. 勾选确认并保存。目录刷新后，已确认且有可售数量的 SKU 会开放加购和付款。缺记录、暂停销售或没有可售件数的选项走询价。
4. 到库存流水核对操作人、记录依据和变动。库存低于已预留时，先核对关联订单。

下单预留、付款失败释放、发货出库都按订单记录的仓位进行。同一请求重试可取得已有订单。支付服务商可能先报失败再报成功，迟到付款会进入履约异常待办。收到异常时，在钱海核对该订单的交易和退款状态，再核对仓库和客户处理结果。待付款订单需核对渠道后才能取消释放库存。两种付款方式都受同一库存规则约束。

## 采购询价

买家从商品颜色、导航或购物车提交询价。后台 **采购询价** 支持按状态和编号筛选、分配负责人、记录美元报价和内部跟进。询价编号是保存回执。业务人员使用买家提供的邮箱跟进。

## Google Search Console

在 Vercel 的 Production 环境将 `GOOGLE_SEARCH_CONSOLE_SERVICE_ACCOUNT_JSON` 设为 Sensitive，使用有权向 CoWin 域名属性提交 Sitemap 的服务账号。保存变量后创建新的生产部署。每周一北京时间 09:00 的任务调用 Search Console Sitemaps API。

后台 **数据同步** 记录 OAuth、提交阶段的错误以及 Google 接收的 HTTP 状态和可取得的读取时间。拥有系统管理权限的人员可立即发起同一提交逻辑。若失败，按阶段检查凭据格式、Google API、域名属性权限和 URL。凭据与 OAuth 响应正文保留在服务端。Google 接收、读取与网页收录分别验收。

## 发布与恢复

- 先在隔离库运行增量迁移和业务回归，测试盘点、并发下单、付款通知及询价。测试订单和测试库存留在隔离库。
- 生产发布核对 Git SHA、Vercel 域名和 `/admin/sync`。查看上线后的结账、回调与任务错误日志。
- 若需恢复，先确保生产交易遵守库存确认规则。上线前旧版本会放行缺库存记录的订单，直接回滚会重新暴露该路径。优先发布保留库存拦截的修复版本。恢复数据库前在隔离分支核对订单、库存及支付记录，确认需要恢复的时间点。
